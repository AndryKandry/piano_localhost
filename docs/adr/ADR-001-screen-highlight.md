# ADR-001: Подсветка — экранные клавиши, не физическая клавиатура

Статус: принято (2026-11-23)

## Контекст

Исходное желание: «подсветка нужных клавиш» на клавиатуре ноутбука — как в
обучающих пианино-симуляторах. Пользователь на MacBook.

Research (`docs/research/03-keyboard-limits.md`): macOS не предоставляет
публичного API адресной подсветки клавиш. Управление подсветкой живёт в
приватных IOKit user client (`AppleKeyboardlight`/`AppleSMC`); публично
доступна только общая яркость всей клавиатуры. Существующий root-хак
(запись напрямую в SMC, github.com/pirate/mac-keyboard-brightness) требует
root, приватных API и не управляет отдельными клавишами.

## Решение

Подсветка реализуется только на экране: экранные фортепианные клавиши
(белые/чёрные) с подписями физических клавиш, подсветка нужных в момент
игры. Физическая подсветка не преследуется ни в каком виде.

## Альтернативы

| Альтернатива | Почему нет |
|--------------|------------|
| Root-хак через SMC/приватные API | Root, приватные API ломаются на обновлениях macOS, всё равно НЕ адресный |
| Внешняя RGB-периферия (Launchpad и т.п.) | Выходит за рамки «клавиатура ноутбука» |

## Последствия

- Весь UX подсказок строится вокруг экрана: падающие ноты + подсветка экранных клавиш.
- Термины: «подсветка» = всегда про экранные клавиши (см. GLOSSARY, Avoid-список).
- Положительное: работает на любом железе/ОС, ноль разрешений.
