# ADR-004: Рендер — Canvas 2D, два слоя; позиция ноты — чистая функция аудио-часов

Статус: принято (2026-11-23)

## Контекст

Падающие ноты Synthesia-style: 30–60 видимых нот @ 60fps на MacBook,
подсветка клавиш, wait-mode (статичные кадры), партии двумя цветами,
синхронизация со звуком.

Research (`docs/research/04-rendering.md`).

## Решение

1. **Canvas 2D, два канваса-слоя**:
   - нижний — экранные клавиши (перерисовка по событию: подсветка/маппинг);
   - верхний — колонки нот + линия удара (полный кадр каждый rAF).
   30–60 объектов — на порядки ниже лимита canvas (~1000+ @ 60fps).
2. **Синхронизация**: каждый кадр читать `AudioContext.currentTime`;
   `t_муз = (ctx.currentTime − t0) × множитель`; позиция ноты — чистая
   функция времени. Инкрементные счётчики запрещены — дрейф невозможен
   по построению. Wait-mode = статичный кадр той же формулой.
3. **Раскладка клавиш**: белые равной ширины, чёрные ≈0.6 ширины белой и
   ~60–65% высоты, позиционируются по границам белых. Единая функция
   раскладки — источник геометрии и для клавиш, и для колонок нот
   (инвариант: колонка всегда над своей клавишей).
4. **Retina обязателен**: буфер = CSS-размер × `devicePixelRatio`,
   `ctx.scale(dpr, dpr)`, рисование в CSS-пикселях, пересчёт при resize.

## Альтернативы

| Альтернатива | Почему нет |
|--------------|------------|
| DOM/CSS transform | Меняющиеся высоты нот + подсветка = layout/paint каждый кадр |
| WebGL/three.js | В экосистеме нужен только для 3D-видео (notefall); оверкилл |

## Последствия

- Никакого UI-фреймворка в зоне канвасов; DOM — только для панелей
  (библиотека, пресеты, настройки).
- OSS-референсы (ReactPianoPlayer MIT, Neothesia GPL — только смотреть,
  код не копировать; лицензии MIDIano/piano-fx не подтверждены).
- Одна функция раскладки = точка изменения при добавлении режимов
  отображения (напр. нотный стан в будущих версиях).
