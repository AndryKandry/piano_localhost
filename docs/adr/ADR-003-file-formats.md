# ADR-003: Разбор файлов — @tonejs/midi; MusicXML своим экстрактором; OSMD отвергнут

Статус: принято (2026-11-23)

## Контекст

Пользователь загружает мелодии: MIDI (.mid) как основной формат, MusicXML —
дополнительно. Нужны: ноты с временем и длительностью в секундах, tempo-карта,
партии рук.

Research (`docs/research/02-midi-musicxml.md`).

## Решение

1. **MIDI — библиотека `@tonejs/midi`** (32KB UMD, TS-типы, стабильна).
   Внимание на API: только `new Midi(await file.arrayBuffer())` и
   `Midi.fromUrl(url)`; методов `fromString`/`fromArrayBuffer` НЕ существует.
2. **Время не конвертируем сами**: `note.time`/`note.duration` уже в секундах,
   посчитаны по tempo-карте (`header.tempos`, PPQ). Свой ticks→sec не нужен.
3. **Внутренняя модель** (канон для всего приложения):
   `{pitch: MIDI 0–127, startTimeSec, durationSec, handPart: 'right'|'left', velocity}`
   + tempoMap мелодии. Множитель скорости — слой плеера поверх секунд,
   BPM файла не меняется.
4. **Партия руки** — каскад: имя MIDI-трека → канал (истор. конвенция
   левая=3/правая=4) → сплит по питчу. Если обе руки в одном треке —
   ручной порог сплита в UI (как «Split From Here» в Synthesia): жёсткая
   автограница даёт артефакты на перекрестьях рук.
5. **MusicXML — свой DOMParser-экстрактор** (XML-схема понятна: `<note>`,
   divisions, `<staff>`, `<voice>`). Руки в MusicXML кодируются явно
   (`<staff>1/2`) — надёжнее MIDI.

## Альтернативы

| Альтернатива | Почему нет |
|--------------|------------|
| opensheetmusicdisplay | Рендерер нотных листов 1.4MB min, playback не поддерживает, вес несоразмерен |
| Свой MIDI-парсер с нуля | Недели работы ради решённой задачи |

## Последствия

- MusicXML-экстрактор — наш код и наш долг (покрытие тегов растёт по нужде);
  MIDI покрывает 95% кейсов.
- Разбор партий — эвристика + ручная коррекция; не обещать «автоматически
  правильно» в UI.
- Не подтверждено research'ом: дословная формулировка midi.org о темпе в
  meta-событии (факт подтверждён, причина — рассуждение).
